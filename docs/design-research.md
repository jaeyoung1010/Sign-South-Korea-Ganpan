# 몰입형 간판 학습 화면 디자인 리서치

작성일: 2026-10-07
적용 대상: `index.html`의 학습 세션

## 조사 기준

- Mobbin의 공개 모바일 탐색 화면에서 실제 출시 앱의 `Photo`, `Carousel`, `Top Navigation Bar`, `Bottom Sheet`, `Full-Screen Overlay`, `Progress Indicator` 사례를 비교했다.
- 콘셉트 시안보다 실제 출시 화면을 우선했다. Mobbin은 스스로를 매주 갱신되는 실제 출시 화면 레퍼런스 라이브러리로 설명한다.
- 스와이프의 발견성과 상태 전환은 공식 모바일 디자인 가이드도 함께 확인했다. SAP Fiori는 가로 캐러셀에서 다음 카드 일부를 보여 스와이프 가능성을 알리고, 전체 화면 카드도 가로 스와이프로 전환하는 방식을 제시한다.

## 선택한 패턴

### 1. 사진을 화면의 주인공으로 사용

간판 사진을 카드 안 작은 이미지로 두지 않고 모바일 화면 전체에 채운다. 사진 위에는 꼭 필요한 진행 상태와 질문만 올린다. 사용자가 먼저 실제 거리 장면을 보고 글자를 찾아야 하는 학습 목표와 가장 잘 맞는다.

### 2. 질문과 정답의 정보 밀도를 분리

- 질문 상태: 하단 어두운 그라데이션 위에 카테고리, 질문, 짧은 안내만 표시한다.
- 정답 상태: 하단 반투명 시트에 한글, 뜻, 단어 분해, 거리 팁을 표시한다.
- 정답 시트는 사진 전체를 가리지 않고 위쪽 장면을 계속 남겨 간판과 뜻의 연결을 유지한다.

### 3. 화면 전체가 움직이는 직접 조작

- 정답 공개 후 사진과 정보 시트가 한 장의 카드처럼 좌우로 이동한다.
- 왼쪽은 `Review`, 오른쪽은 `Got it`으로 기존 학습 모델을 유지한다.
- 현재 카드가 움직일 때 뒤의 다음 사진이 확대·밝아지며 드러난다. 카드 스택의 깊이와 다음 콘텐츠 존재를 동시에 알려준다.
- 제스처를 모르는 사용자도 완료할 수 있도록 하단 버튼을 항상 함께 제공한다.

### 4. 상단 컨트롤은 사진 위의 유리 질감 오버레이

닫기, 현재 순서, 더보기, 진행 바, 확대 버튼만 남겼다. 원형 반투명 버튼과 흰색 진행 바로 사진과 컨트롤의 층을 구분하되 장면을 가리지 않는다.

## 인터랙션 규칙

| 상태 | 가로 드래그 | 하단 버튼 | 정보 표현 |
|---|---|---|---|
| 질문 | 30px 범위의 저항 후 원위치 | Show answer | 사진 + 질문 오버레이 |
| 정답 | 카드 전체가 손가락을 따라 이동 | Review / Got it | 사진 + 하단 정답 시트 |
| 임계값 통과 | 88px 이후 방향별 평가 | 동일한 평가 실행 | 다음 사진이 뒤에서 전면으로 전환 |
| 기기 경계 이탈 | 좌표를 화면 경계에 제한하고 터치 종료로 처리 | 해당 없음 | 카드가 기기 프레임 밖의 포인터를 추적하지 않음 |

## 적용하지 않은 패턴

- 제스처만 제공하는 방식: 초행 사용자의 발견성과 접근성이 낮아 버튼을 병행했다.
- 정답을 별도 화면으로 여는 방식: 간판 사진과 뜻의 시각적 연결이 끊어진다.
- 사진 위에 많은 컨트롤을 놓는 방식: 글자 찾기라는 핵심 과제를 방해한다.
- 자동으로 넘어가는 캐러셀: 학습자가 읽고 회상할 시간을 통제해야 하므로 사용하지 않았다.
