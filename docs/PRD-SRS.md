## 1. 문서 목적

이 문서는 제품 요구사항 문서(PRD)와 소프트웨어 요구사항 명세서(SRS)를 하나로 통합한다. 제품이 해결할 문제, 목표 사용자, MVP 범위, 사용자 경험, 기능·데이터·품질·보안 요구사항, 수용 기준을 한곳에 정의하며 기획·디자인·개발·콘텐츠 제작·QA가 같은 기준으로 의사결정하도록 하는 것이 목적이다.

## 2. 제품 요약

### 2.1 한 문장 정의

간판한글은 실제 한국 간판 사진을 카드로 보여주고, 사용자가 뜻과 읽는 법을 확인한 뒤 Tinder처럼 좌우로 스와이프하며 생활 한국어를 짧게 익히는 모바일 앱이다.

### 2.2 비전

교재 속 문장보다 길거리에서 먼저 만나는 한국어를 이해하게 하여, 외국인이 한국을 더 자신 있게 탐색하도록 돕는다.

### 2.3 핵심 가치

- **실전성:** 한국에서 실제로 마주치는 간판과 표현을 학습한다.
- **낮은 진입 장벽:** 한 손으로 보고, 누르고, 좌우로 넘기는 짧은 흐름을 제공한다.
- **맥락 학습:** 번역만 제공하지 않고 단어 구성, 쓰이는 장소, 문화적 맥락을 함께 설명한다.
- **반복 학습:** 모르는 카드는 자연스럽게 다시 등장하고, 아는 카드는 빈도가 줄어든다.

## 3. 배경과 문제 정의

한글의 자모와 발음 규칙을 배운 외국인도 실제 한국 거리에서는 다음 문제를 겪는다.

1. 간판의 글자체, 세로쓰기, 축약어, 외래어 때문에 교재에서 배운 한글과 다르게 느껴진다.
2. 글자를 소리 내어 읽어도 단어의 뜻이나 가게의 성격을 알기 어렵다.
3. 지도·번역 앱은 즉시 해석에는 유용하지만 표현을 기억하게 만드는 반복 학습 경험은 부족하다.
4. 기존 어학 앱은 문법과 일반 어휘 중심이라 한국 방문 중 자주 보는 표현의 우선순위가 낮다.
5. 여행 준비 중인 사용자는 긴 강의보다 하루 수 분의 가벼운 학습을 선호한다.

따라서 제품은 실제 간판을 중심으로 **보기 → 추측하기 → 뜻 확인하기 → 자기평가하기 → 다시 만나기**의 반복 루프를 제공해야 한다.

## 4. 제품 원칙

1. 한 카드에는 하나의 핵심 표현만 가르친다.
2. 사용자는 3초 안에 다음 행동을 이해할 수 있어야 한다.
3. 한글을 읽을 수 있는 사용자를 대상으로 하므로 로마자 표기는 기본적으로 숨긴다.
4. 실제 맥락을 유지하되 학습을 방해하는 시각 정보는 크롭·강조 표시로 정리한다.
5. 스와이프 방향은 앱 전체에서 바뀌지 않는다.
6. 정답을 확인한 후 자기평가하게 하여 학습 피드백 없는 넘기기를 방지한다.
7. 재미를 위해 정확성·문화적 맥락·접근성을 희생하지 않는다.

## 5. 결정 사항과 전제

요청에 명시되지 않은 항목은 MVP를 빠르게 검증할 수 있도록 다음과 같이 결정한다.

| 항목 | MVP 결정 | 근거 |
|---|---|---|
| 작업명 | 간판한글 | 정식 브랜드 결정 전 사용할 가칭 |
| 지원 플랫폼 | iOS·Android 동시 지원 | 관광객의 기기 편중을 가정하지 않음 |
| 앱 기본 언어 | 영어 | 초기 콘텐츠와 QA 범위를 통제하며 가장 넓은 사용자층 검증 |
| 대상 숙련도 | CEFR A1~A2 상당, 한글 해독 가능 | 한글 자모 교육은 핵심 문제에서 제외 |
| 콘텐츠 | 운영자가 검수한 실제 간판 이미지 | OCR 오인식과 부적절한 콘텐츠 위험을 낮춤 |
| 카드 판정 | 왼쪽 `Review`, 오른쪽 `Got it` | 가장 단순하고 반복 가능한 두 상태 |
| 정답 공개 | 정답을 연 후 스와이프 활성화 | 학습 내용을 보지 않고 카드를 소비하는 문제 방지 |
| 세션 길이 | 기본 10장, 약 3~5분 | 여행 준비 사용자의 짧은 이용 맥락에 적합 |
| 로그인 | 게스트 우선, 선택적 계정 연결 | 첫 사용 마찰 최소화 |
| 수익화 | MVP에서 제외 | 학습 가치와 유지율을 먼저 검증 |
| 위치 기능 | 사용하지 않음 | 위치 권한 없이 핵심 가치를 제공하고 개인정보 범위 축소 |
| 카메라 OCR | MVP 이후 | 인식 정확도·안전·콘텐츠 설명 품질을 별도로 검증해야 함 |

## 6. 목표와 비목표

### 6.1 MVP 목표

- 사용자가 설명 없이 첫 학습 세션을 시작하고 완료할 수 있다.
- 실제 간판의 핵심 표현을 읽고 뜻과 사용 맥락을 이해할 수 있다.
- 좌우 스와이프로 아는 카드와 복습할 카드를 분류할 수 있다.
- 복습 대상이 이후 세션에 적절한 간격으로 다시 등장한다.
- 콘텐츠 운영자가 앱 업데이트 없이 카드를 등록·검수·게시할 수 있다.
- 게스트도 즉시 사용할 수 있고, 계정 연결 시 학습 기록을 보존할 수 있다.

### 6.2 MVP 비목표

- 한글 자모부터 가르치는 입문 과정
- 실시간 카메라 촬영 및 OCR 번역
- 자유 문장 번역, 대화형 튜터, 발음 채점
- 사용자 간 팔로우·댓글·랭킹 등 소셜 기능
- 지도 기반 주변 간판 탐색 또는 길찾기
- 사용자가 직접 올린 사진의 공개 피드
- 광고, 구독, 인앱 결제
- 영어 이외 인터페이스의 정식 지원

## 7. 사용자 정의

### 7.1 1차 페르소나: 여행 준비자 Alex

- 한국 방문을 1~3개월 앞둔 20~40대
- 한글을 천천히 읽을 수 있고 기본 인사말을 안다.
- 하루 5분 이하로 실용적인 표현을 익히고 싶다.
- 식당, 카페, 교통, 쇼핑 간판을 알아보는 데 가장 관심이 있다.

### 7.2 2차 페르소나: 한국 체류자 Mina

- 한국에 도착했거나 단기 체류 중이다.
- 거리에서 본 표현을 다음에 알아볼 수 있도록 반복하고 싶다.
- 긴 설명보다 이미지와 짧은 문화 팁을 선호한다.

### 7.3 제외 사용자

- 아직 한글 글자와 기본 음가를 모르는 완전 입문자
- TOPIK 고급 수준의 문법·작문 학습이 필요한 사용자
- 번역 결과만 즉시 필요한 사용자

## 8. 핵심 사용자 여정

### 8.1 첫 이용

1. 사용자가 앱을 실행한다.
2. 앱의 목적과 스와이프 의미를 2~3개 화면에서 확인한다.
3. 자기 수준과 관심 카테고리를 선택하거나 건너뛴다.
4. 게스트로 첫 10장 세션을 시작한다.
5. 간판 사진을 보고 표현의 읽기와 뜻을 추측한다.
6. `Show answer`를 눌러 정답과 설명을 확인한다.
7. 왼쪽 `Review` 또는 오른쪽 `Got it`으로 스와이프한다.
8. 10장 완료 후 학습 결과와 복습 예정 수를 확인한다.

### 8.2 재방문

1. 홈에서 오늘의 복습 수와 예상 소요 시간을 확인한다.
2. 복습 카드와 새 카드가 섞인 세션을 시작한다.
3. 같은 학습 루프를 반복한다.
4. 진행 화면에서 익힌 표현, 연속 학습일, 카테고리별 진척을 확인한다.

### 8.3 실수 복구

1. 사용자가 카드를 반대 방향으로 스와이프한다.
2. 다음 카드에서 `Undo`를 한 번 누른다.
3. 직전 카드와 학습 상태가 복구된다.

## 9. 정보 구조

앱의 하단 내비게이션은 세 영역으로 제한한다.

1. **Learn:** 오늘의 세션, 새 카드, 복습 카드
2. **Progress:** 학습 통계, 익힌 표현, 복습 대기 목록
3. **Settings:** 언어, 로마자 표기, 오디오, 알림, 계정, 개인정보

학습 중에는 하단 내비게이션을 숨겨 카드와 제스처에 집중하게 한다.

## 10. 핵심 학습 경험

### 10.1 카드 앞면

- 모바일 뷰포트를 끝까지 채우는 실제 간판 사진
- 학습 대상 영역의 은은한 강조 표시
- 카테고리와 난이도
- `What does this sign say?` 안내 문구
- `Show answer` 버튼
- 이미지 확대 기능

간판 사진은 별도 카드 테두리 없이 상단 진행 영역과 하단 동작 영역의 배경까지 이어지는 풀블리드 방식으로 표시한다. 가로형 원본을 세로 화면에 표시할 때는 핵심 간판 글자를 잘라내지 않고 전체 사진을 선명하게 유지하며, 남는 영역은 동일 이미지의 블러 확장 레이어로 채운다. 카드 앞면에는 정답 한국어 텍스트, 번역, 로마자 표기를 노출하지 않는다.

### 10.2 카드 뒷면

- 간판에서 읽어야 할 정확한 한국어 표기
- 자연스러운 영어 의미
- 단어 또는 형태소 단위 풀이
- 오디오 재생
- 짧은 사용 맥락 또는 문화 팁
- 선택적 로마자 표기
- 왼쪽 `Review`, 오른쪽 `Got it` 안내

정답은 사진과 분리된 새 화면이 아니라 사진 하단의 반투명 바텀 시트로 열린다. 설명은 모바일 한 화면에서 핵심 내용이 보이도록 작성하며, 문화 팁은 원칙적으로 영어 140자 이내로 한다.

### 10.3 스와이프 규칙

- 정답을 공개하기 전에는 좌우 스와이프로 판정할 수 없다.
- 왼쪽 스와이프는 `Review`이며 카드가 복습 큐에 들어간다.
- 오른쪽 스와이프는 `Got it`이며 숙련도가 상승한다.
- 카드가 화면 너비의 25% 이상 이동하거나 빠른 플릭 동작이 감지되면 판정한다.
- 임계값 미만에서 손을 놓으면 카드는 중앙으로 복귀한다.
- 이동 중 방향에 따라 `REVIEW` 또는 `GOT IT` 오버레이를 표시한다.
- 사진, 강조 영역, 정답 시트는 한 장의 카드처럼 함께 이동하고 뒤의 다음 간판 사진이 점진적으로 드러나야 한다.
- 동일 기능의 버튼을 함께 제공하여 제스처 사용이 어려운 사용자도 학습할 수 있게 한다.
- 직전 판정은 다음 카드를 판정하기 전까지 한 번 취소할 수 있다.

### 10.4 반복 알고리즘(MVP)

MVP는 설명 가능하고 조정하기 쉬운 규칙 기반 방식을 사용한다.

- 처음 보는 카드에서 `Review`: 현재 세션의 3~5장 뒤에 한 번 더 노출하고 다음 날 복습 예약
- 복습 카드에서 `Review`: 숙련 단계를 0으로 되돌리고 다음 날 복습 예약
- 처음 보는 카드에서 `Got it`: 3일 뒤 복습 예약
- 연속 `Got it`: 7일 → 21일 → 60일 순으로 간격 증가
- 60일 단계에서 다시 `Got it`: `Mastered`로 분류하되 90일 이후 재노출 가능
- 하루 복습 카드가 많으면 기한이 오래 지난 카드와 `Review` 횟수가 많은 카드를 우선 노출
- 기본 세션 구성은 복습 30%, 새 카드 70%이며 밀린 복습이 있으면 복습 비율을 최대 70%까지 높임

서버는 다음 복습 시각과 숙련 단계를 저장하며, 클라이언트가 오프라인일 때의 판정은 로컬에 기록한 뒤 연결 시 순서대로 동기화한다.

## 11. 기능 요구사항

우선순위는 Must(MVP 필수), Should(가능하면 MVP), Could(MVP 이후)로 구분한다.

### 11.1 온보딩과 설정

| ID | 우선순위 | 요구사항 |
|---|---|---|
| FR-ONB-001 | Must | 시스템은 첫 실행 시 제품 목적을 세 문장 이내로 설명해야 한다. |
| FR-ONB-002 | Must | 시스템은 실제 카드 또는 모의 카드로 좌우 스와이프 의미를 안내해야 한다. |
| FR-ONB-003 | Must | 사용자는 초급·초중급 중 자기 수준을 선택하거나 건너뛸 수 있어야 한다. |
| FR-ONB-004 | Should | 사용자는 식당, 카페, 교통, 쇼핑, 편의시설, 주의·안내 중 관심 카테고리를 선택할 수 있어야 한다. |
| FR-ONB-005 | Must | 사용자는 로그인 없이 학습을 시작할 수 있어야 한다. |
| FR-ONB-006 | Must | 사용자는 설정에서 로마자 표기 노출 여부를 변경할 수 있어야 하며 기본값은 꺼짐이어야 한다. |
| FR-ONB-007 | Must | 온보딩을 완료한 사용자는 다음 실행부터 홈으로 이동해야 한다. |

### 11.2 홈과 세션

| ID | 우선순위 | 요구사항 |
|---|---|---|
| FR-SES-001 | Must | 홈은 오늘의 권장 세션, 복습 대기 수, 예상 소요 시간을 표시해야 한다. |

- 속어·축약어·브랜드 언어는 일반 표현으로 오해되지 않게 표시한다.
- 북측 표현, 비표준 표기, 지역어는 별도 라벨 없이 초급 피드에 넣지 않는다.
- 상호·로고·저작물의 사용 권한을 게시 전에 확인한다.
- 얼굴, 차량 번호, 결제 정보, 상세 주소 등 불필요한 개인정보를 제거한다.
- TTS를 사용할 경우 한국어 원어민 검수 후 게시한다.

## 13. 시스템 요구사항

### 13.1 논리 구성

시스템은 다음 구성요소로 나눈다.

- **모바일 클라이언트:** 온보딩, 카드 세션, 로컬 캐시, 오프라인 판정, 진행 화면
- **애플리케이션 API:** 세션 구성, 학습 기록, 계정, 동기화, 신고 처리
- **관계형 데이터베이스:** 사용자, 카드 메타데이터, 학습 상태, 이벤트 참조 데이터
- **객체 저장소·CDN:** 간판 이미지와 발음 오디오 제공
- **인증 서비스:** Apple·Google 로그인과 토큰 관리
- **콘텐츠 운영 도구:** 카드 작성, 검수, 게시, 신고 처리
- **분석·모니터링:** 제품 이벤트, 장애, 성능, 충돌 수집

특정 프레임워크와 클라우드 사업자는 기술 설계 단계에서 결정한다. API 계약과 데이터 모델은 플랫폼에 종속되지 않게 유지한다.

### 13.2 주요 API 동작

| 동작 | 설명 |
|---|---|
| 세션 요청 | 사용자 수준·관심사·복습 상태를 반영한 카드 목록과 콘텐츠 버전 반환 |
| 판정 기록 | 카드, 방향, 정답 공개 여부, 발생 시각, 세션, 고유 요청 ID 저장 |
| 판정 취소 | 직전 판정을 상쇄하고 학습 상태 재계산 |
| 진행 조회 | 전체·카테고리별 학습 및 복습 상태 집계 반환 |
| 동기화 | 마지막 동기화 이후 변경 사항을 양방향 병합 |
| 신고 등록 | 카드와 신고 유형, 선택 설명 등록 |
| 계정 삭제 | 인증·학습·프로필 데이터 삭제 작업 접수 및 상태 제공 |

모든 쓰기 요청은 클라이언트가 생성한 고유 요청 ID를 받아 재시도 시 중복 반영되지 않아야 한다.

### 14.2 데이터 규칙

- 한 사용자와 카드 조합의 현재 `LearningState`는 하나만 존재해야 한다.
- `SwipeEvent.request_id`는 사용자 범위에서 유일해야 한다.
- 게시된 카드 버전은 과거 세션 재현을 위해 삭제하지 않고 보관한다.
- 삭제 요청이 완료되면 개인 식별자와 학습 기록의 연결을 제거한다.
- 분석용 데이터는 가능한 경우 집계·가명화하고 원본 계정 식별자를 사용하지 않는다.

보조 지표:

- 온보딩 완료율
- 첫 세션 시작률 및 완료율
- 사용자당 주간 완료 카드 수
- `Review` 카드의 7일 내 재학습률
- D1·D7·D30 유지율
- 정답 공개 전 카드 이탈률
- 신고율과 신고 해결 시간
- 이미지 로딩 실패율, 동기화 실패율, 충돌 없는 세션 비율

### 16.3 공개 베타 성공 기준

다음 수치는 제품 가설을 검증하기 위한 초기 목표이며 실제 베타 데이터로 조정한다.

- 온보딩 시작 사용자의 70% 이상이 첫 세션을 시작
- 첫 세션 시작 사용자의 75% 이상이 10장을 완료
- 첫 세션 완료 사용자의 D7 유지율 25% 이상
- `Review` 판정 카드의 7일 내 재학습률 40% 이상
- 카드 신고율 1% 미만
- 충돌 없는 세션 비율 99.5% 이상

## 17. 수용 기준

### AC-01 첫 세션 진입

**Given** 신규 사용자가 앱을 처음 실행했고  
**When** 온보딩을 완료하거나 허용된 단계에서 건너뛰면  
**Then** 계정 생성 없이 10장 학습 세션을 시작할 수 있다.

### AC-02 정답 확인 전 판정 방지

**Given** 카드 앞면이 표시되어 있고 정답을 열지 않았을 때  
**When** 사용자가 좌우로 스와이프하면  
**Then** 카드는 판정되지 않고 중앙으로 돌아오며 `Show answer first` 안내가 표시된다.

### AC-03 좌우 판정

**Given** 정답을 확인한 카드에서  
**When** 사용자가 왼쪽으로 임계값 이상 스와이프하면  
**Then** `Review` 이벤트가 한 번 저장되고 다음 카드가 표시된다.  
**When** 오른쪽으로 스와이프하면  
**Then** `Got it` 이벤트가 한 번 저장되고 다음 카드가 표시된다.

### AC-04 버튼 대체 동작

**Given** 정답이 열린 카드에서  
**When** 사용자가 `Review` 또는 `Got it` 버튼을 누르면  
**Then** 동일 방향 스와이프와 같은 상태 변경, 애니메이션, 기록이 발생한다.

### AC-05 실행 취소

**Given** 사용자가 직전 카드를 판정했고 현재 카드에는 아직 판정하지 않았을 때  
**When** `Undo`를 누르면  
**Then** 직전 카드가 복구되고 해당 판정과 복습 일정이 취소된다.

### AC-06 오프라인 학습

**Given** 세션이 기기에 저장되어 있고 네트워크가 끊겼을 때  
**When** 사용자가 여러 카드를 판정하고 앱을 다시 실행하면  
**Then** 판정과 세션 진행도가 유지되며 연결 복구 후 서버에 중복 없이 반영된다.

### AC-07 이미지 실패

**Given** 카드 이미지를 불러올 수 없을 때  
**When** 카드가 표시되면  
**Then** 오류 상태와 재시도·건너뛰기 기능이 보이고, 건너뛴 카드는 학습 결과에 포함되지 않는다.

### AC-08 복습 일정

**Given** 사용자가 처음 본 카드에 `Review`를 판정했을 때  
**When** 세션에 충분한 카드가 남아 있으면  
**Then** 해당 카드는 3~5장 뒤 한 번 재등장하며 다음 날에도 복습 대상으로 예약된다.

### AC-09 세션 복구

**Given** 사용자가 10장 중 4장을 완료한 상태에서 앱이 종료되었을 때  
**When** 앱을 다시 열면  
**Then** 완료한 4장의 기록을 유지하고 5번째 카드부터 계속할 수 있다.

### AC-10 계정 삭제

**Given** 로그인 사용자가 설정에서 계정 삭제를 선택했을 때  
**When** 명확한 확인 절차를 완료하면  
**Then** 삭제 요청 상태와 예상 처리 기간이 안내되고 새 인증 토큰 발급이 중단된다.

### AC-11 접근성

**Given** 화면 읽기 도구와 모션 감소가 켜져 있을 때  
**When** 사용자가 카드 한 장을 학습하면  
**Then** 이미지 맥락, 정답, 두 판정 버튼, 진행도를 순서대로 이용할 수 있고 큰 카드 퇴장 애니메이션은 축소된다.

### AC-12 콘텐츠 게시

**Given** 운영자가 새 카드를 검수 대기 상태로 만들었을 때  
**When** 필수 메타데이터나 이미지 권리 증빙이 누락되어 있으면  
**Then** 시스템은 게시를 거부하고 누락 항목을 표시한다.

## 18. QA 범위

### 18.1 필수 테스트

- 각 지원 OS에서 온보딩부터 세션 완료까지의 정상 흐름
- 느린 네트워크, 오프라인, 연결 전환, 요청 재시도
- 연속 빠른 스와이프와 중복 탭에서 중복 이벤트 방지
- 앱 종료·충돌·OS 메모리 회수 뒤 세션 복구
- 게스트 기록의 계정 병합과 다중 기기 충돌
- 큰 글자, 화면 읽기, 모션 감소, 색 대비
- 다양한 화면 비율에서 이미지 크롭과 정답 레이아웃
- 콘텐츠 비활성화 또는 버전 변경 중 진행 세션의 동작
- 계정 삭제와 로그·백업의 개인정보 처리
- 운영 도구의 역할별 권한과 감사 기록

### 18.2 출시 차단 조건

- 판정 또는 학습 기록이 유실되거나 중복되는 결함
- 스와이프 방향과 저장 결과가 불일치하는 결함
- 개인정보 또는 인증 토큰이 로그에 노출되는 결함
- 이미지 사용 권한이나 개인정보 검수가 되지 않은 카드 게시
- 화면 읽기 사용자에게 대체 판정 수단이 없는 상태
- 세션 완료를 막는 재현 가능한 충돌

## 19. 단계별 출시 계획

### 0단계: 프로토타입

- 30장 내외의 로컬 카드
- 카드 앞·뒷면과 좌우 스와이프
- 5명 이상의 대상 사용자로 방향 이해도와 설명 길이 검증

### 1단계: 비공개 알파

- API, 계정 없이 게스트 학습, 규칙 기반 복습
- 100장 이상의 검수 콘텐츠
- 오프라인 세션, 기본 분석, 오류 수집
- 20~50명의 테스트 사용자

### 2단계: 공개 베타(MVP)

- 300장 이상 콘텐츠
- 선택적 계정 연결과 동기화
- 콘텐츠 운영 도구와 신고 기능
- 복습 알림, 접근성 점검, 운영 대시보드

### 3단계: 학습 확장

- 인터페이스 다국어 지원
- 개인화 추천 고도화
- 듣기·발음·상황별 미니 퀴즈
- 사용자 요청에 따른 여행 일정별 학습 묶음

### 4단계: 현장 기능 검증

- 카메라 OCR 기반 개인 간판 학습
- 촬영 이미지의 기기 내 처리 우선 검토
- OCR 신뢰도 표시와 사용자 교정
- 안전·저작권·개인정보 검증 후 제한적 출시

## 21. MVP 이후 결정이 필요한 항목

다음 항목은 현재 개발을 막지 않지만 공개 출시 전에 제품 책임자가 확정해야 한다.

3. 계정 체계의 최종 제공자와 연령 제한
4. 장기 수익 모델(무료, 구독, 여행 파트너십 등)
5. 콘텐츠 직접 촬영·라이선스 구매·제휴의 비중과 예산
6. 알림 기본 빈도와 지역별 개인정보·마케팅 동의 문구
7. 공개 베타의 대상 국가, 모집 규모, 운영 기간
8. 카메라 OCR 기능의 기기 내 처리 여부와 원본 이미지 보존 정책

## 22. 완료 정의

MVP는 다음 조건을 모두 만족할 때 완료로 본다.

- Must 기능 요구사항과 AC-01~AC-12가 모두 통과한다.
- 최소 300장의 권리·개인정보·언어 검수가 완료된 카드가 게시된다.
- 지원 OS에서 출시 차단 결함이 없다.
- 개인정보 처리방침, 이용약관, 콘텐츠 신고·삭제 절차가 준비된다.
- 성능·안정성·접근성 기준이 실제 기기 테스트에서 충족된다.
- 분석 이벤트와 운영 대시보드가 개인정보 원칙에 맞게 검증된다.
- 장애 대응, 콘텐츠 비활성화, 계정 삭제 요청의 운영 담당과 절차가 정해진다.

## 23. 화면 설계 범위와 기준

### 23.1 화면 설계 목표

이하 명세는 디자이너가 추가 제품 결정을 기다리지 않고 모바일 앱과 콘텐츠 운영 도구의 로우·미드 피델리티 화면 설계서를 작성할 수 있는 수준을 목표로 한다. 브랜드 로고와 일러스트 스타일은 가칭 단계이므로 교체 가능하게 설계하되, 정보 구조·동작·상태·문구·접근성 기준은 고정한다.

### 23.2 기준 화면과 반응형 범위

| 항목 | 기준 |
|---|---|
| 모바일 기준 프레임 | 390 × 844pt |
| 최소 검증 프레임 | 360 × 800dp |
| 대형 검증 프레임 | 430 × 932pt |
| 그리드 | 4pt 기본 단위, 주요 간격은 8pt 배수 |
| 좌우 안전 여백 | 기본 20pt, 카드 학습 화면은 16pt |
| 최소 터치 영역 | 44 × 44pt(iOS), 48 × 48dp(Android)를 모두 만족하도록 48 × 48 기준 적용 |
| 상단 영역 | OS 안전 영역 아래부터 배치 |
| 하단 영역 | 홈 인디케이터·시스템 내비게이션 안전 영역을 침범하지 않음 |
| 방향 | 세로 화면 고정. 이미지 확대 화면만 기기 회전을 허용할 수 있음 |
| 콘텐츠 폭 | 대형 화면에서도 본문 최대 560pt, 학습 카드 최대 480pt |

### 23.3 화면 설계 산출물 단위

각 화면 설계서에는 다음 항목을 표시한다.

1. 화면 ID와 화면명
2. 진입 조건과 이탈 경로
3. 기본·로딩·빈 상태·오류·오프라인 상태
4. 스크롤 영역과 고정 영역
5. 탭·스와이프·뒤로가기 동작
6. 노출 문구와 동적 데이터 규칙
7. 접근성 읽기 순서와 대체 조작
8. 연결되는 기능 요구사항 ID

## 24. 시각·컴포넌트 시스템

### 24.1 디자인 방향

- 실제 거리 사진이 주인공이 되도록 앱 크롬은 밝고 절제된 중립색을 사용한다.
- 여행의 활기와 학습의 신뢰감을 함께 주는 파란색을 주 색상으로 사용한다.
- `Review`와 `Got it`은 색, 아이콘, 텍스트를 동시에 사용해 구분한다.
- 둥근 카드와 부드러운 이동 애니메이션을 사용하되 게임 UI처럼 과도하게 장식하지 않는다.
- 브랜드가 확정되기 전까지 아래 색상은 접근성 검증과 화면 일관성을 위한 작업용 토큰으로 본다.

### 24.6 이미지 표현 규칙

- 기본 카드 이미지는 가로 4:3 비율의 `cover`로 표시한다.
- 원본이 세로형이면 핵심 표현이 잘리지 않도록 콘텐츠의 `focus_region`을 기준으로 자동 크롭한다.
- 학습 대상 영역은 2pt 흰색 테두리와 30% 검정 외곽 음영으로 표시하며 정답 공개 전에도 사용할 수 있다.
- 정답 공개 후 핵심 영역 강조는 유지하되, 나머지 이미지를 지나치게 흐리게 처리하지 않는다.
- 이미지 위 텍스트에는 그라데이션 또는 불투명 배경을 적용해 사진과 관계없이 대비를 확보한다.
- 얼굴·차량 번호 등 흐림 처리는 클라이언트 효과가 아니라 게시 이미지 자체에 반영한다.

### 24.7 모션과 햅틱

| 동작 | 기본 모션 | 햅틱 |
|---|---|---|
| 정답 공개 | 220ms ease-out, 하단 정보 영역 확장 | 없음 |
| 임계값 미만 스와이프 복귀 | 180ms spring | 없음 |
| 카드 판정 | 240ms ease-in, 좌우 퇴장 후 다음 카드 80ms 겹침 | 가벼운 선택 피드백 |
| 세션 완료 | 300ms 숫자·요약 등장 | 성공 피드백 1회 |
| 오류 | 흔들기 모션 사용 금지 | 경고 피드백은 치명적 실패에만 1회 |

모션 감소가 활성화되면 카드가 회전하지 않고 100ms 페이드로 교체되며, 완료 축하 애니메이션은 정적 상태로 대체된다.

## 26. 전역 내비게이션과 라우팅

### 26.1 내비게이션 구조

```text
Launch
├─ First run → Welcome → Tutorial → Level → Interests → Learn home
└─ Returning user → Learn home

Bottom navigation
├─ Learn
│  ├─ Session loading → Card front ⇄ Card answer → Session complete
│  └─ Session length / Reminder prompt
├─ Progress
│  ├─ Review list → Card detail
│  └─ Mastered list → Card detail
└─ Settings
   ├─ Learning preferences
   ├─ Reminder
   ├─ Account → Sign in / Delete account
   └─ Help & legal
```

### 26.2 라우팅 우선순위

앱 실행 시 다음 순서로 목적 화면을 결정한다.

1. 유효한 딥링크 또는 복습 알림이 있고 온보딩이 완료되었으면 해당 목적 화면으로 이동한다.
2. 완료되지 않은 학습 세션이 있으면 홈에서 `Resume session` 카드가 최상단에 표시된다. 자동으로 세션을 열지는 않는다.
3. 온보딩이 완료되지 않았으면 ONB-01로 이동한다.
4. 그 외에는 HOME-01로 이동한다.

### 26.3 뒤로가기와 종료

- 온보딩에서는 ONB-02부터 뒤로갈 수 있으며 ONB-01에서 시스템 뒤로가기는 앱을 종료한다.
- 학습 세션에서 뒤로가기를 누르면 `Leave this session?` 바텀 시트를 표시한다.
- 세션 이탈 시 완료 카드 기록은 보존하고 홈에 `Resume session`을 표시한다.
- 이미지 확대, 바텀 시트, 다이얼로그가 열려 있으면 시스템 뒤로가기는 해당 레이어를 먼저 닫는다.
- 하단 탭의 루트에서 같은 탭을 다시 누르면 목록을 맨 위로 스크롤한다.
- 탭 전환 시 각 탭의 스크롤 위치를 현재 앱 실행 동안 보존한다.

## 27. 모바일 화면 상세 명세

### 27.1 APP-00 Launch

**목적:** 앱 초기화 중 빈 화면을 방지하고 온보딩·홈 라우팅을 결정한다.

**레이아웃:**

- 전체 화면에 `color.background`를 사용한다.
- 작업용 워드마크 `Sign Korean`을 화면 중앙에 배치한다.
- 400ms 안에 라우팅이 끝나면 로딩 표시를 노출하지 않는다.
- 400ms가 지나면 워드마크 아래 24pt 원형 진행 표시를 노출한다.
- 버전 정보는 화면에 표시하지 않고 접근성 트리에서도 제외한다.

**동작과 상태:**

- 로컬 상태 조회는 네트워크와 무관하게 완료되어야 한다.
- 원격 설정을 3초 안에 받지 못하면 마지막 정상 설정 또는 앱 기본값으로 진입한다.
- 필수 로컬 데이터가 손상되면 `We couldn't start the app` 오류와 `Try again` 버튼을 표시한다.
- 스플래시 화면에 광고, 권한 요청, 마케팅 문구를 넣지 않는다.

### 27.2 ONB-01 Welcome

**목적:** 제품 가치와 대상 사용자를 한 화면에서 이해시킨다.

**상단부터 하단 레이아웃:**

1. 상단 안전 영역 아래 높이 24의 4단계 페이지 표시 중 1단계
2. 높이 280~320의 대표 간판 사진 콜라주 또는 한 장의 히어로 이미지

**콘텐츠 순서:**

- 화면 하단에 좌우 16, 간격 12의 동일 폭 버튼 두 개를 고정한다.
- 왼쪽 Secondary button: 되돌림 화살표 아이콘 + `Review`
- 오른쪽 Primary 역할의 청록 버튼: 체크 아이콘 + `Got it`
- 버튼 위에 첫 세션의 첫 3장까지만 `Swipe or tap` Caption을 표시한다.
- 카드 내용은 하단 행동 영역 뒤로 가리지 않도록 마지막에 행동 영역 높이만큼 여백을 둔다.

**가로 스와이프와 세로 스크롤 충돌 처리:**

- 터치 이동이 12pt를 넘은 시점에 방향을 잠근다.
- `|dx| > 1.2 × |dy|`이면 가로 스와이프로, 그 외에는 카드 내부 세로 스크롤로 처리한다.
- 버튼, 오디오, 링크에서 시작한 터치는 카드 스와이프로 전환하지 않는다.
- 수평 판정 중에는 세로 스크롤을 멈추고, 수직 판정 중에는 카드 회전·이동을 멈춘다.
- 화면 읽기 또는 스위치 제어 사용 시 제스처 안내를 숨기고 두 버튼을 기본 조작으로 안내한다.

**판정 피드백:**

- 카드가 왼쪽으로 이동하면 왼쪽 위에 호박색 `REVIEW` + 되돌림 아이콘을 표시한다.
- 카드가 오른쪽으로 이동하면 오른쪽 위에 청록색 `GOT IT` + 체크 아이콘을 표시한다.
- 오버레이 불투명도는 이동률 8%에서 시작해 25%에서 100%가 된다.
- 판정 후 다음 카드가 표시되며 하단 Snackbar `Marked as Review` 또는 `Marked as Got it`과 `Undo`를 4초간 표시한다.
- 다음 카드를 판정하면 이전 Snackbar와 실행 취소 기회는 즉시 사라진다.

**콘텐츠 예외:**

- 한국어가 두 줄을 넘으면 글자 크기를 Title 3까지 줄이고 그 이상은 내부 스크롤이 아니라 전체 문구를 두 줄로 편집한다.
- 단어 풀이가 4개를 넘으면 핵심 4개만 카드에 표시하고 `More details`는 MVP에서 제공하지 않는다.
- 오디오가 없거나 실패하면 오디오 버튼을 비활성화하고 `Audio unavailable` 접근성 설명을 제공한다.

  - 제목: `Want a reminder when reviews are ready?`
  - 행동: `Set a reminder` → SET-03
  - 닫기: `Not now`; 닫으면 최소 7일간 다시 제안하지 않는다.
- 색종이 효과는 첫 세션 완료 시에만 1초 이내로 사용하며 모션 감소 시 표시하지 않는다.

## 28. 공통 상태와 피드백

### 28.1 상태 우선순위

한 화면에 여러 상태가 동시에 발생하면 다음 순서로 사용자 행동을 결정한다.

1. 데이터 손실 또는 보안 위험이 있는 차단 오류
2. 필수 콘텐츠를 표시할 수 없는 오류
3. 오프라인 상태
4. 로딩 상태
5. 빈 상태
6. 일반 콘텐츠

오프라인이어도 캐시 콘텐츠를 사용할 수 있으면 화면을 차단하지 않고 배너만 표시한다.

### 28.2 전역 상태 매트릭스

| 상황 | UI 표현 | 사용 가능 행동 |
|---|---|---|
| 네트워크 단절·캐시 있음 | 상단 배너 `You're offline. Progress will sync later.` | 학습·판정·탐색 가능 |
| 네트워크 단절·캐시 없음 | 화면 내 오류 `Connect to load signs.` | 재시도·이전 화면 |
| 서버 5xx | 화면 내 오류 또는 Snackbar | 재시도, 저장된 콘텐츠 계속 사용 |
| 인증 만료 | 비차단 배너 `Sign in again to keep syncing.` | 게스트처럼 학습 가능, 재로그인 |
| 콘텐츠 삭제됨 | `This sign is no longer available.` | 목록으로 돌아가기 |
| 동기화 충돌 | 최신 이벤트 시각과 고유 ID로 자동 병합 | 사용자에게 충돌 선택을 요구하지 않음 |
| 저장 공간 부족 | `Free up space to save more signs offline.` | 온라인 학습 또는 설정 이동 |
| 앱 업데이트 필수 | 차단 화면, 사유와 스토어 이동 | `Update app`만 제공 |

### 28.3 로딩 표시 규칙

- 300ms 미만 작업은 진행 표시를 생략한다.
- 화면 구조를 아는 목록·카드는 Skeleton을 사용한다.
- 사용자가 시작한 저장·제출은 해당 버튼 안에 진행 표시를 사용한다.
- 전체 화면 스피너는 Launch와 인증 제공자 전환 외에는 사용하지 않는다.
- 로딩 중에도 뒤로가기 또는 취소가 안전하면 항상 제공한다.

### 28.4 오류 문구 규칙

- 실패 원인을 사용자가 해결할 수 있는 수준으로 설명한다.
- 내부 오류 코드, HTTP 상태, 기술 용어는 기본 화면에 노출하지 않는다.
- `Something went wrong`만 단독으로 사용하지 않는다.
- 재시도가 유효하면 `Try again`, 연결이 필요하면 `Check connection`, 지원이 필요하면 `Contact support`를 사용한다.

## 29. UI 문구와 콘텐츠 스타일

### 29.1 제품 보이스

- 짧고 직접적이며 격려하되 유아적으로 말하지 않는다.
- 사용자의 한국어 수준을 평가하거나 실패를 비난하지 않는다.
- `Wrong`, `Failed`, `You forgot` 대신 `Review`, `Try again`, `Not yet`을 사용한다.
- 한 문장에는 하나의 행동만 설명한다.
- 영어 UI에서는 문장형 대소문자(sentence case)를 사용한다.
- 느낌표는 세션 완료 같은 긍정적 순간에 제한적으로 사용한다.
- 간판의 자연스러운 의미와 단어의 직역이 다르면 둘을 명시적으로 구분한다.

### 29.2 고정 용어

| 개념 | 표시 문구 | 사용하지 않을 문구 |
|---|---|---|
| 왼쪽 판정 | `Review` | `No`, `Wrong`, `Dislike` |
| 오른쪽 판정 | `Got it` | `Like`, `Pass`, `Perfect` |
| 정답 공개 | `Show answer` | `Flip`, `Reveal solution` |
| 새 학습 카드 | `New sign` | `Unseen item` |
| 복습 예정 | `Due for review` | `Expired`, `Overdue lesson` |
| 숙련 완료 | `Mastered` | `Finished forever` |
| 학습 단위 | `Sign` | `Question`, `Post` |
| 학습 묶음 | `Session` | `Deck`, `Course` |

### 29.4 동적 문구 규칙

- 숫자 1일 때 단수형을 사용한다: `1 sign`, `1 minute`, `1 day`.
- 예상 시간은 반올림한 정수 분으로 표시하고 1분 미만이면 `Less than a minute`를 사용한다.
- 상대 날짜는 오늘·내일까지만 `Today`, `Tomorrow`로 표시하고 그 이후는 현지화된 짧은 날짜를 사용한다.
- 연속 학습일 1일은 `1 day`, 2일 이상은 `{n} days`이며 0일은 표시하지 않는다.
- 사용자 이름은 MVP에서 수집하지 않으므로 인사말에 이름을 넣지 않는다.
- 콘텐츠 번역에 따옴표가 필요하면 영어 의미에 스마트 큰따옴표를 사용하되 단어 풀이에는 사용하지 않는다.

## 30. 반응형·접근성 상세 규칙

### 30.1 작은 화면

- 높이가 700 이하인 기기에서는 카드 이미지 높이를 먼저 줄이고 본문 글자 크기는 줄이지 않는다.
- LEARN-02의 질문과 버튼은 첫 화면 안에 보여야 하며 카테고리 칩은 필요하면 한 줄로 축약한다.
- LEARN-03은 이미지 높이를 160까지 줄이고 정답 이하 내용을 세로 스크롤한다.
- 하단 고정 행동 영역은 키보드가 열리면 REPORT-01을 제외하고 키보드 위로 올라가지 않는다.

### 30.2 큰 화면과 태블릿

- 화면 폭 600 이상에서는 본문과 학습 카드를 중앙 정렬하고 최대 폭을 각각 560, 480으로 제한한다.
- 태블릿 세로 화면에서도 하단 내비게이션을 유지한다.
- 가로 태블릿은 MVP 공식 지원 범위가 아니지만 레이아웃이 깨지지 않아야 하며 콘텐츠 최대 폭을 유지한다.
- 콘텐츠를 불필요하게 2열로 재배치하지 않는다. CMS만 데스크톱 2열을 사용한다.

### 30.3 동적 글자 크기

- 기본~150%에서는 명시된 레이아웃을 유지한다.
- 151~200%에서는 버튼이 여러 줄 높이로 늘고, 요약 카드 3개는 가로 3열에서 세로 목록으로 전환한다.
- 200%에서 카드 하단 두 판정 버튼이 한 행에 들어가지 않으면 세로로 쌓되 `Review`가 위, `Got it`이 아래에 온다.
- 텍스트를 잘라 핵심 의미를 숨기지 않는다. 사용자 생성 자유 입력 목록만 두 줄 말줄임을 허용한다.

### 30.4 화면 읽기 순서

- 시각적 순서와 의미 순서를 일치시킨다.
- 이미지의 대체 텍스트는 앞면에서 `A Korean storefront sign. Focus area highlighted.`처럼 정답을 포함하지 않는다.
- 뒷면에서는 `Storefront sign reading {korean_text}.`처럼 정답을 포함할 수 있다.
- 진행 막대는 `Sign 3 of 10, 30 percent`로 한 요소처럼 읽는다.
- 판정 버튼은 `Review this sign later`와 `Mark this sign as understood` 접근성 라벨을 사용한다.
- 카드 스와이프는 화면 읽기 사용자에게 필수 동작으로 안내하지 않는다.
- Snackbar의 결과 문구는 자동으로 읽되 `Undo`로 포커스를 강제 이동하지 않는다.

### 30.5 키보드·스위치·외부 입력

- iOS Switch Control, Android Switch Access로 모든 행동에 도달할 수 있어야 한다.
- 외부 키보드에서 Tab으로 포커스를 이동하고 Enter/Space로 실행한다.
- 학습 화면 단축키는 왼쪽 화살표 `Review`, 오른쪽 화살표 `Got it`이지만 정답 공개 이후에만 활성화한다.
- Esc는 이미지 뷰어·시트·다이얼로그를 닫고, 학습 루트에서는 종료 확인 시트를 연다.
- 포커스 표시가 사진이나 배경과 관계없이 보이도록 2pt 고대비 외곽선을 사용한다.

### 30.6 색각과 모션

- Review는 되돌림 화살표, Got it은 체크를 항상 함께 표시한다.
- 그래프 범례에는 색뿐 아니라 직접 라벨과 값을 표시한다.
- 자동 재생 애니메이션은 5초를 넘지 않는다.
- 깜박임은 초당 3회를 넘지 않으며, 화면 전체 플래시를 사용하지 않는다.

## 31. 콘텐츠 운영 도구 화면 명세

운영 도구는 데스크톱 웹 기준 최소 폭 1280px로 설계한다. 모바일 운영은 MVP 범위에서 제외한다.

### 31.1 CMS-01 Sign in

- 조직용 SSO 또는 이메일 인증 진입 버튼
- 제품 로고, `Content Studio`, 환경 배지(`Production` 또는 `Staging`)
- 인증 실패 시 사용자에게 권한 요청 담당자를 안내한다.
- 운영 도구는 공개 회원가입을 제공하지 않는다.

### 31.2 CMS-02 Card list

**레이아웃:**

- 왼쪽 폭 240 고정 내비게이션: Cards, Review queue, Reports, Audit log
- 상단: `Cards`, 검색, `Create card`
- 필터: 상태, 카테고리, 난이도, 권리 만료, 수정자
- 데이터 테이블 열:
  - 썸네일
  - Korean text
  - English meaning
  - Category
  - Difficulty
  - Status
  - Rights expiry
  - Updated at/by
  - 더보기
- 행 선택 시 CMS-03을 같은 탭에서 연다.
- 다중 선택 행동은 `Archive`, `Assign reviewer`만 제공하며 `Publish` 일괄 처리는 MVP에서 제외한다.
- 기본 정렬은 최근 수정 순이다.
- 검색은 한국어 원문, 정규화 텍스트, 영어 의미, 카드 ID를 대상으로 한다.

**상태:**

- 결과 없음: `No cards match these filters.` + `Clear filters`
- 카드 없음: `Create your first sign card.` + `Create card`
- 로딩 실패: 기존 테이블을 유지할 수 있으면 상단 배너와 재시도, 유지할 수 없으면 화면 오류

### 31.3 CMS-03 Card editor

**2열 레이아웃:**

- 상단 고정 바: 뒤로가기, 카드 ID·상태, `Save draft`, 상태별 대표 행동
- 왼쪽 60% 편집 폼, 오른쪽 40% 모바일 카드 미리보기
- 오른쪽 미리보기는 LEARN-02·03 토글과 390 × 844 기준 프레임을 제공한다.

**편집 섹션 순서:**

1. **Image**
   - 원본 업로드, 썸네일
   - focus region 드래그·크기 조정
   - 개인정보 흐림 영역 추가·삭제
   - 원본 크기, 파일 형식, 용량 표시
2. **Core text**
   - Korean text
   - Normalized text
   - English meaning
   - Romanization
3. **Word breakdown**
   - 최대 4개 행, 한국어 조각·영어 풀이, 드래그 정렬
4. **Learning context**
   - Category
   - Difficulty
   - Street note, 140자 권장 카운터
5. **Audio**
   - 오디오 업로드 또는 승인된 생성 요청
   - 재생·교체·삭제
6. **Rights & privacy**
   - Rights owner
   - Source
   - Usage scope
   - Expiry date 또는 No expiry
   - Evidence attachment
   - Privacy review 체크리스트
7. **Internal notes**
   - 사용자 앱에 보이지 않는 운영 메모

**검증:**

- 필수 필드는 라벨에 `Required`를 표시하고 저장 시점과 검수 제출 시점의 검증을 구분한다.
- 초안 저장은 이미지와 Korean text만 있으면 가능하다.
- 검수 제출에는 12.2절의 모든 필수 필드와 권리 증빙이 필요하다.
- 오류는 상단 요약과 각 필드에 함께 표시한다.
- 저장하지 않은 변경이 있을 때 이탈하면 확인 다이얼로그를 표시한다.
- 자동 저장은 MVP에서 제공하지 않고 마지막 저장 시각을 상단에 표시한다.

### 31.4 CMS-04 Review queue and review detail

**Review queue:**

- 검수 대기 카드를 제출 시각이 오래된 순으로 표시한다.
- 필터: 담당자, 카테고리, 난이도, 권리 상태
- 목록에 제출자, 대기 시간, 필수 검사 통과 여부를 표시한다.

**Review detail:**

- 왼쪽에 원본·처리 이미지 비교, 오른쪽에 전체 메타데이터와 모바일 미리보기
- 검수 체크리스트:
  - 한국어 원문이 이미지와 일치함
  - 영어 의미가 맥락에 맞음
  - 단어 풀이가 정확함
  - 발음이 정확함
  - 이미지 권리가 유효함
  - 개인정보 검수가 완료됨
  - 난이도와 카테고리가 적절함
- 하단 고정 행동:
  - `Request changes` — 사유 필수
  - `Approve` — 모든 체크 완료 시 활성화
  - `Publish` — Approve 권한과 Publish 권한이 같은 사용자에게 있을 때만, 아니면 승인 후 게시 대기
- 검수자는 자신이 마지막으로 편집한 카드를 단독 승인할 수 없도록 역할 정책에서 제한한다.

### 31.5 CMS-05 Report queue

- 상단 요약: Open, High priority, Resolved today
- 필터: 신고 유형, 카드 상태, 접수일, 처리 상태
- `Image is inappropriate or private` 유형을 High priority로 자동 분류한다.
- 테이블 열: 우선순위, 카드, 유형, 신고 수, 최초·최근 접수, 담당자, 상태
- 같은 카드·유형의 신고는 한 항목으로 묶고 횟수를 표시한다.
- 상세 패널에서 이미지, 현재 콘텐츠, 익명화된 신고 설명을 확인한다.
- 행동:
  - `Unpublish card` — 즉시 앱에서 제외, 확인 다이얼로그
  - `Edit card`
  - `Resolve — fixed`
  - `Resolve — no issue`
- 해결 사유는 감사 로그에 남기며 사용자 개인에게 결과를 알리는 기능은 MVP에서 제외한다.

### 31.6 CMS-06 Audit log

- 수정 불가 읽기 전용 테이블
- 열: 발생 시각, 운영자, 행동, 대상 유형·ID, 요약, IP/세션 참조
- 필터: 날짜, 운영자, 행동, 대상 ID
- 행을 열면 변경 전후 값을 구조화된 diff로 표시한다.
- 인증 토큰, 원본 개인정보, 자유 입력의 민감정보는 로그에 저장하지 않는다.
- CSV 내보내기는 관리자 권한에서만 제공하고 내보내기 자체도 감사 이벤트로 기록한다.

## 33. 화면 설계 산출물 완료 기준

### 33.1 디자이너 산출물

화면 설계 단계는 다음 산출물이 준비되면 완료로 본다.

- 25절의 모든 모바일 화면에 대한 360·390 기준 프레임
- HOME-01, LEARN-02, LEARN-03, DONE-01, PROG-01의 200% 글자 크기 프레임
- HOME-01, LEARN-01~03, PROG-01~02의 로딩·빈 상태·오류·오프라인 변형
- 카드 앞면→정답→왼쪽/오른쪽 판정→Undo→완료를 연결한 프로토타입
- 온보딩, 중단 세션 복구, 계정 연결, 알림 허용, 계정 삭제 프로토타입
- 공통 컴포넌트와 색상·타이포·간격 토큰 라이브러리
- CMS-02~05의 1280px 데스크톱 화면
- 모든 화면에 화면 ID, 연결 화면, 고정/스크롤 영역, 접근성 주석 표시

### 33.2 필수 프로토타입 검증 시나리오

1. 신규 사용자가 앱 설명 없이 첫 10장 세션을 시작할 수 있는가?
2. 사용자가 정답 전에는 스와이프할 수 없음을 이해하는가?
3. 사용자가 왼쪽과 오른쪽의 의미를 첫 세션 후에도 기억하는가?
4. 긴 정답 화면에서 세로 스크롤과 가로 스와이프를 구분할 수 있는가?
5. 잘못 판정한 사용자가 Undo를 발견하고 복구할 수 있는가?
6. 중단한 세션이 저장되었다는 사실과 재개 위치를 이해하는가?
7. 화면 읽기 사용자가 제스처 없이 세션을 완료할 수 있는가?
8. 운영자가 누락된 권리 정보가 있는 카드를 게시할 수 없음을 이해하는가?

### 33.3 설계 승인 체크리스트

- [ ] 모든 핵심 화면에 대표 행동이 하나만 강조되어 있다.
- [ ] 스와이프와 같은 대체 버튼이 항상 제공된다.
- [ ] 정답 공개 전·후 상태가 색 외의 요소로 구분된다.
- [ ] 작은 화면과 큰 글자에서 핵심 버튼이 가려지지 않는다.
- [ ] 오프라인·오류 상태에서 이미 완료한 학습이 사라진 것처럼 보이지 않는다.
- [ ] 계정 연결과 알림 권한을 학습 시작 전에 강제하지 않는다.
- [ ] 이미지 확대에서 정답 공개 상태를 유지한다.
- [ ] Review와 Got it의 방향·색·아이콘·문구가 모든 화면에서 일치한다.
- [ ] 운영 도구에서 초안 저장, 검수 제출, 승인, 게시의 차이가 명확하다.
- [ ] 화면 문구가 29절의 고정 용어와 일치한다.
